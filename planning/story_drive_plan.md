# 이야기 드라이브(가칭) 기획서

현대자동차그룹 차량용 앱 개발 공모전 출품 기획안
작성 기준일 2026년 11월 4일

내비게이션에 목적지를 찍으면 가는 길을 미리 보고 아이 나이에 맞는 동화를 지어, 이동하는 동안 차가 아이에게 들려주는 Pleos Connect 앱이다. 동화는 창밖의 실제 호수와 산을 배경으로 쓰고, 비가 오면 호수가 불어 주인공이 건너지 못하고 날이 저물면 숲이 어둑해지는 식으로 차가 느끼는 주변 환경에 따라 이야기가 바뀐다. 아이는 갈림길마다 목소리로 주인공의 선택을 정한다.

이야기가 중간에 끊겨도 지금까지의 내용을 '이야기 상태'로 저장해 두었다가, 다시 이어 들을 때 남은 시간과 주변 환경에 맞춰 남은 줄거리를 다시 짠다. 터널처럼 인터넷이 끊기는 구간에 대비해 이야기를 미리 받아 두고, 목소리는 차 안 엔진으로 낸다.

목표는 아이에게 이동 시간을 여행의 일부로 바꿔 주는 것이다. 현대자동차그룹이 공모전 주제로 제시한 '패밀리·동승자 케어'와 '인카 엔터테인먼트'를 함께 겨냥한다.

현재 단계는 기획이다. 아래의 SDK 지원 범위 중 '확인 필요'로 표시한 항목은 아직 검증하지 않았다.

## 1 서비스 소개

**앱명:** 이야기 드라이브(가칭)

**한 줄 소개:** 가는 길이 동화가 되는 차

**대상:** 미취학·초등 저학년 아이와 함께 차로 이동하는 가족

## 2 기획 배경과 고객 문제

**아이에게 긴 이동은 지루하다.** 아이가 보채면 보호자는 뒷좌석 영상에 기대거나, 운전 중에 아이를 달래느라 주의가 흐트러진다.

**창밖 풍경이 그냥 지나간다.** 호수와 산을 지나도 아이에게는 이름 없는 풍경일 뿐이고, 이동은 여행이 아니라 기다림이 된다.

**기존 오디오 콘텐츠는 지금 이 길을 모른다.** 동화와 오디오북은 정해진 내용이라 지금 지나는 길이나 날씨와 상관이 없다. 해외의 위치 기반 오디오 투어 앱(Autio, GuideAlong)은 스마트폰 앱이고, 공개된 설명 기준으로 정해진 투어를 위치에 맞춰 들려주는 방식이다.

이 문제의 강도는 아이 동반 가족 인터뷰로 검증한다.

## 3 핵심 경험과 사용 흐름

| 시점 | 일어나는 일 |
| --- | --- |
| 출발 전 (주차 중) | 아이 프로필(별명, 나이, 좋아하는 것)을 고르고 내비게이션에 목적지를 찍는다. 앱은 남은 시간과 경로상의 실제 장소를 보고 동화 설계도를 만든다. |
| 주행 중 | 바로 다음 챕터를 그때의 날씨·밤낮·위치에 맞춰 만들어 음성으로 들려준다. 갈림길에서는 아이에게 묻고 음성으로 대답을 받는다. |
| 끊겼을 때 | 이야기 상태를 저장한다. 다시 이어 들을 때 남은 시간과 현재 환경에 맞춰 남은 줄거리를 다시 짠다. |
| 도착 | 남은 거리에 맞춰 결말로 모으고, 주차하면 오늘의 동화가 그림책처럼 화면에 남는다. |

주행 중에는 화면 조작이 없다. 모든 상호작용은 음성으로 하고, 화면 기능은 주차 중에만 연다.

## 4 주변 환경과의 상호작용

| 환경 | 차가 아는 방법 | 이야기 반응 예 |
| --- | --- | --- |
| 비 | 와이퍼 작동 (Vehicle SDK Wiper) | 호수가 불어 주인공이 건너지 못한다 |
| 밤·어두워짐 | 전조등 켜짐 (Vehicle SDK Light) + 시각 | 숲이 어둑해지고 반딧불이가 길을 비춘다 |
| 추위 | 외기온 (AAOS 표준 속성) | 호숫가에 살얼음이 낀다 |
| 실제 호수·산을 지남 | 위치·진행 방향 (FusedLocation) | "지금 오른쪽 창밖에 보이는 그 호수"가 이야기 속 장소로 등장한다 |
| 막힘 | 속도 저하·남은 시간 증가 (AAOS 속도, NaviHelper) | 쉬어 가는 장면을 넣어 이야기를 늘린다 |
| 터널 | 위치 + 전조등 자동 점등 | 주인공이 깜깜한 동굴로 들어간다 |
| 도착 임박 | 남은 거리 (NaviHelper) | 결말로 수렴한다 |
| 휴게소 정차 | 기어 P (Vehicle SDK Gear) | 챕터를 마무리하고 쉰다 |

환경 반응은 이야기 속 사건으로만 쓴다. 운전자에게 어떤 행동도 요구하지 않는다.

## 5 이야기 생성과 재구성

### 동화 설계도

목적지를 찍으면 한 번 만든다. 주인공과 세계관, 큰 줄거리, 챕터 수, 경로상의 실제 장소가 이야기 속 어디에 나올지를 정한다. 챕터 수와 길이는 남은 시간에 맞추고, 결말은 도착 시점에 맞춘다.

### 챕터 단위 생성

전체를 한꺼번에 확정하지 않고, 바로 다음 1~2개 챕터를 그때의 환경과 아이의 선택을 반영해 만든다. 설계도는 방향을 잡고, 챕터는 순간에 반응한다.

### 이야기 상태

줄거리 요약 문장 하나만 저장하면 다시 생성할 때 이름이 바뀌거나 앞의 복선이 사라지기 쉽다. 그래서 정해진 칸이 있는 상태로 저장하고, 재구성할 때 이 상태를 압축 프롬프트로 넘긴다.

- 등장인물과 세계관 (이름, 성격, 장소)
- 지금까지의 줄거리 요약
- 아직 풀리지 않은 사건 (예: 호수를 건너야 함)
- 아이가 고른 선택들
- 현재 챕터 위치와 마지막 환경 (비·밤 여부)

### 끊김 유형별 재개

| 끊김 | 재개 방식 |
| --- | --- |
| 내비 안내·통화 (짧음) | 끊긴 문장부터 그대로 이어서 |
| 휴게소·시동 끔 (김) | 지난 이야기를 30초 정도로 회상한 뒤, 남은 시간으로 다시 설계 |
| 경로 변경·정체로 도착 시간이 바뀜 | 끊기지 않아도 남은 챕터 수를 계속 조정 |
| 아이가 "그만"이라고 함 | 상태 저장 후 멈춤 |

## 6 인터넷이 끊기는 구간 대비

동화는 글자라서 여행 전체 분량도 몇 KB에 불과하다. 그래서 3단으로 대비한다.

1. **출발 때 기본본 전체 받기:** 남은 시간에 맞춘 전체 챕터를 한 번에 생성해 차에 저장한다. 인터넷이 아예 안 돼도 처음부터 끝까지 이어진다.
2. **연결될 때 앞부분 고쳐 쓰기:** 연결되어 있는 동안 바로 앞 1~2개 챕터를 그 순간의 환경과 선택에 맞춰 다시 만들어 기본본을 덮어쓴다.
3. **변수는 갈래로 미리 받기:** 비가 올 때, 어두워질 때, 아이가 A·B 중 무엇을 고를 때의 짧은 변형 장면을 함께 받아 두어 오프라인에서도 바로 반응한다.

**터널 감지와 버퍼:** 경로 정보로 터널 위치를 알 수 있으면 진입 전에 터널 시간만큼 받아 둔다. 모를 때는 최소 10분 분량을 항상 차에 둔다. 국내에서 가장 긴 도로 터널인 인제양양터널(약 11km)도 시속 90km로 7분 남짓이다.

**목소리도 오프라인:** 음성 합성은 `ON_DEVICE` 또는 `HYBRID`(끊기면 차 안 엔진으로 자동 전환) 모드로 쓴다. 아이 대답 인식도 `ON_DEVICE`로 하고, 터널 안에서는 정해진 보기 중에서만 고르게 한다.

**터널을 장면으로:** 터널 진입 순간 미리 받아 둔 동굴 장면을 들려주고, 나오는 순간 "동굴 밖으로 나오니 해가 반짝!"으로 잇는다.

**최후 대체:** 버퍼가 바닥나도 끊기지 않게 앱 안에 끝말잇기, 퀴즈, 쉬어 가는 장면을 넣어 둔다. 연결이 돌아오면 이야기 상태를 서버로 보내 현재 위치와 남은 시간 기준으로 다시 잇는다.

## 7 안전 원칙

- 주행 중에는 화면 조작 없이 음성으로만 동작한다. 화면에는 '이야기 중'만 표시한다. 플랫폼 주행 제한 상태(`CarUxRestrictions`)에 따라 화면을 잠그고, Distraction Optimization을 선언한다.
- 말은 아이와 동승자를 향해 한다. 운전자에게 대답을 요구하지 않고, "창밖을 보세요" 같은 표현은 동승자에게 하는 말로 쓴다.
- 내비게이션 회전 안내 직전이나 주의 구간에서는 이야기를 잠깐 멈춘다.
- 재생 전에 오디오 포커스를 요청하고, 음악은 줄이며, 내비 안내·통화·긴급 알림에는 양보한다. 음성 비서 Gleo가 호출되면 즉시 멈춘다. 음성 앞에는 150~200 ms 무음(pre-roll)을 넣어 첫 음절이 잘리지 않게 한다.
- 아이 콘텐츠 안전: 나이별 금지 주제를 정하고, 밤 장면이 무섭지 않게 수위를 조절한다. 실제 장소에 대한 사실은 확인된 정보만 쓰고, 동화 속 상상과 섞지 않는다.

## 8 기술 구성

### 차량 데이터와 SDK

| 기능 | 사용 SDK·API | 권한 | 확인 상태 |
| --- | --- | --- | --- |
| 목적지·남은 시간·남은 거리 | NaviHelper | `NAVI_ROUTE` | 남은 시간·거리 제공 확인(릴리스 노트). 경로 좌표 제공 여부는 확인 필요 |
| 위치·진행 방향·장소 근접 알림 | FusedLocation | `FUSED_LOCATION` | 콘솔 사용 가능 여부 확인 필요. 현재 코드는 NaviHelper 위치로 대체 |
| 음성 출력 | TextToSpeech (`ON_DEVICE`/`HYBRID`, ko-KR) | `TTS_SERVICE` | 콘솔 사용 가능 여부 확인 필요 |
| 음성 인식 | SpeechToText (`ON_DEVICE`) | `STT_SERVICE` | 콘솔 사용 가능 여부 확인 필요 |
| 비 | Vehicle SDK Wiper | `CAR_WINDOWS` | 차종별 지원 확인(`checkXxxCapabilities`) |
| 밤 | Vehicle SDK Light | `CAR_LIGHTS` | 차종별 지원 확인 |
| 외기온 | AAOS `ENV_OUTSIDE_TEMPERATURE` | `CAR_EXTERIOR_ENVIRONMENT` | 차종별 지원 확인 |
| 속도 | AAOS `PERF_VEHICLE_SPEED` | `CAR_SPEED` | 코드 반영됨 |
| 주차 판정 | Vehicle SDK Gear | `CAR_POWERTRAIN` | 코드 반영됨 |
| 주행 제한 상태 | AAOS `CarUxRestrictionsManager` | — | 코드 반영됨 |

모두 조회 권한이며, 사전 승인이 필요한 제어 권한(`CONTROL_CAR_*`)은 쓰지 않는다.

### 서버

- **이야기 생성:** 외부 생성형 AI API를 호출하는 앱 서버를 둔다. Pleos LLM SDK는 2026년 10월 지원이 종료되었다.
- **장소 정보:** 경로상의 호수·산·명소 정보는 공공 관광 데이터(예: 한국관광공사 TourAPI)를 후보로 검토한다.
- **보내는 정보 최소화:** 서버에는 원시 좌표 대신 장소 이름, 환경 요약, 이야기 상태만 보낸다.

### 앱 카테고리

Music/Audio를 후보로 둔다. Pleos 문서에서 오디오북 청취처럼 주행 중 제한적으로 허용될 수 있다고 예시한 범주라서다. 확정 전에 운영사무국에 확인한다.

## 9 확인이 필요한 사항

| 항목 | 왜 중요한가 | 확인 방법 |
| --- | --- | --- |
| TTS·STT·FusedLocation 콘솔 사용 가능 여부 | 기획의 뼈대 | Playground 프로젝트의 SDK 메뉴 |
| NaviHelper가 경로 좌표를 주는지 | 출발 전 설계도와 장소 선정 | 에뮬레이터에서 `onRouteStarted`, `onTripInfo`, `onRouteStateInfo` 값 기록 |
| 터널이 주의 지점 유형에 포함되는지 | 버퍼 타이밍 | 에뮬레이터에서 `onCautionPointInfo` 값 기록 |
| 에뮬레이터에서 GPS 경로 재생(GPX) 가능 여부 | 시연 영상 | Android 에뮬레이터 확장 컨트롤 |
| Music/Audio 카테고리로 주행 중 사용 허용 여부 | 핵심 사용 시점 | 운영사무국 문의 |
| 실제 차량의 통신 데이터 사용 조건 | 서버 생성 비용 | 운영사무국 문의 |

경로 좌표를 받을 수 없으면 대안은 두 가지다. 차가 향하는 방향 기준으로 앞쪽 일정 거리 안의 장소를 주기적으로 찾거나, 외부 길찾기 API로 경로를 따로 받는다.

## 10 첫 버전 범위와 시연

**첫 버전:** 아이 프로필 1명, 목적지 설정 후 설계도 생성, 챕터 생성·재생, 환경 반응 2종(비·밤), 갈림길 선택(보기형), 끊김 후 재개, 터널 대비 버퍼, 도착 후 오늘의 동화 화면.

**후속 범위:** 자유 질문에 대한 대답, 여러 아이 프로필, 캐릭터 목소리, 형제 함께 참여, 여행 앨범 공유.

**시연 경로 후보:** 서울에서 춘천 (북한강, 의암호 등 경유). 시연 경로 하나의 장소 정보와 이야기 품질을 손으로 다듬는다.

**시연 장면:**
1. 목적지를 찍으면 동화가 시작된다.
2. 의암호에 가까워지면 "오른쪽 창밖"의 호수가 이야기에 등장한다.
3. Virtual Console에서 와이퍼를 켜면 그 자리에서 "비가 오기 시작했어, 호수가 불어나고 있어!"로 바뀐다.
4. 아이가 음성으로 주인공의 선택을 정한다.
5. 터널(인터넷 끊김)에서는 미리 받아 둔 동굴 장면이 이어진다.
6. 휴게소에서 P단으로 멈췄다가 다시 출발하면 짧은 회상 후 이어진다.
7. 도착에 맞춰 결말이 나오고, 주차 후 그림책 화면이 남는다.

시뮬레이션 장면에는 에뮬레이터 데이터임을 표시한다.

## 11 기존 서비스와의 차이

## 13 사업성 (가설)

- **첫 고객:** 주말이나 연휴에 1시간 이상 차로 이동하는, Pleos Connect 차량을 가진 아이 동반 가족.
- **확장 방향:** 지자체·관광 콘텐츠 제휴(지역 이야기 팩), 캐릭터·성우 프리미엄 목소리, 지명·자연을 배우는 교육 콘텐츠, 렌터카·카셰어링 가족 패키지.
- **핵심 지표 정의:** 여행당 끝까지 들은 비율, 갈림길 응답률, 다음 여행에서 다시 켠 비율, 월간 이용자 수(MAU). 목표치는 초기 사용자 인터뷰 후 정한다.

## 14 개인정보

- 아이 정보는 별명·나이·좋아하는 것만 받고 차량에 저장한다. 서버에는 이야기 생성에 필요한 최소값만 보낸다.
- 음성은 인식 결과 텍스트만 쓰고 녹음은 저장하지 않는다.
- 원시 위치 좌표의 서버 전송을 최소화한다.
- 보호자 동의 후 사용하고, 아이 프로필과 기록을 언제든 지울 수 있게 한다.
